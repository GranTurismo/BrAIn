BrAIn
A browser your AI can drive. One process, a real desktop window, and a built-in MCP server exposing every part of the browser as tools.

Browse like normal

BrAIn works like any browser: type a URL or search in the address bar, middle-click links for new tabs, right-click tabs for their menu, drag tabs to reorder, and use the ⋮ menu for find, zoom, bookmarks, print, view-source, fullscreen and always-on-top. Bookmarks and history persist between launches.

Copy as Markdown: Ctrl+Shift+M (or ⋮ → Copy page as Markdown, or right-click selected text) puts the page — or just your selection — on the clipboard as clean Markdown: headings, links, lists, tables and code, without menus, banners or scripts. Paste it straight into an AI chat or your notes.

Ask before risky actions: when an AI agent is about to click something that looks like paying, deleting, sending or agreeing (or submit a card form), BrAIn holds the action and asks you: Deny, Allow once, or Allow this site for 10 minutes. No answer in 90 seconds counts as no. Search, login and add-to-cart are never interrupted. Turn it on or off in ⋮ → Agent asks before risky actions. Flows you approved run without asking at each step. It cannot see inside scripts the agent runs with evaluate, so keep the agent paused (Ctrl+Shift+.) if you need a hard stop.

Your turn: when an AI agent reaches a step only you can do — logging in, a CAPTCHA, a 2FA code — it asks for you. BrAIn brings the tab forward and shows a card; do the step in the page yourself (the agent never sees what you type), then press Done, or I can’t do this to tell it to stop. If you don’t answer, the agent is told so after a few minutes.

Record a flow: ⋮ → Record a flow…, do the task once by hand, then press Stop. Name it, tick any typed value you want callers to be able to change, and save. It appears in Flows as a pending flow; approve it and every AI agent can run it as a single tool. Passwords and card numbers are never recorded: they become arguments you supply each run. It starts from the page you were on and records clicks, typing, choices, checkboxes and Enter in this tab.

Rewind — time travel for pages

Turn it on from ⋮ → Rewind (or Ctrl+Shift+Y) and a scrubber appears under the toolbar: drag left and the page reverts to what it showed minutes ago — text, layout and scroll position, frozen in a read-only view. Live jumps back to the present, and the search box finds which past snapshot contained some text (an old price, a deleted paragraph).

Off by default — recording a page costs extra CPU and memory, so nothing runs until you enable it. Snapshots are gzip-compressed and kept in memory only: nothing touches disk, and everything is forgotten when the tab closes or the app quits. Rewind never records private tabs, login pages (any page with a password field) or sites you exclude (⚙ → Don't record this site). Budgets (⚙) cap how long snapshots are kept and how much RAM they may use; the AI agent only sees the history if you allow it separately.

Connect an AI via MCP

BrAIn hosts an MCP server over stdio — the AI client launches it directly. Point your client's MCP config at the binary:

Open your client's MCP settings — Claude Desktop: %APPDATA%\Claude\claude_desktop_config.json (Win) / ~/Library/Application Support/Claude/claude_desktop_config.json (mac), Cursor: ~/.cursor/mcp.json, Devin: ~/.config/devin/mcp_config.json.
Add the brain server block shown below for your platform.
Restart the client — a BrAIn window opens and the agent sees all browser_* tools.
Ask things like "open github, find my unread notifications" — the agent navigates, reads the page and clicks for you.
{
  "mcpServers": {
    "brain": {
      "command": "C:\\path\\to\\BrAIn.exe"
    }
  }
}
{
  "mcpServers": {
    "brain": {
      "command": "/usr/local/share/dotnet/dotnet",
      "args": ["/path/to/BrAIn.dll"]
    }
  }
}

On macOS there is no .exe — the client runs dotnet on the built DLL. Use the absolute dotnet path (which dotnet) and DLL path: GUI-launched clients don't see your shell PATH. Or publish once — dotnet publish -c Release -r osx-arm64 --self-contained — and point "command" straight at the native binary.

Optional args: "args": ["https://example.com"] opens a start page, "--cdp-port", "9333" pins the DevTools port, "--no-toolbar" hides the browser chrome.

Each client spawns its own BrAIn window — disconnecting the client (closing stdin) shuts that browser down cleanly.

What the AI can do

The server exposes ~35 tools covering the whole browser:

navigate / back / forward / reload accessibility snapshot click · type · hover · scroll screenshots · PDF tabs: new / switch / close window & viewport control zoom run JavaScript console log network requests event listeners page as Markdown rewind history (opt-in) cookies

Typical agent flow: browser_navigate → browser_snapshot (gives element refs like e5) → browser_click / browser_type → browser_screenshot to verify.
